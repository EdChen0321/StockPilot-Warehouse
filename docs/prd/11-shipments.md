# StockPilot｜出貨管理 PRD

本文件說明出貨管理的使用情境、操作流程、庫存規則與驗收條件。

## 1. 要解決的問題

讓出貨人員從建單、加入商品到完成出貨，都能核對「本單用了哪些實體件、還有哪些可用庫存、操作更正後數字如何變化」，避免同一件被不同單占用、重複扣庫，以及取消後搶回已分給別單的商品。

**使用者故事：** 身為出貨人員，我希望輸入出貨單號後逐件加入商品，核對後完成出貨；若需要更正，也能追查原件與操作歷史。

**本次範圍：** 建立主副單、逐件掃碼、FIFO 配貨、完成／取消／重開、庫存與歷史核對。實際退貨與櫃位設定屬相關功能，本篇只定義出貨時需遵守的條件。

## 2. 適用情境與流程邊界

本篇以**倉管自行建單、逐件加入商品**為日常主流程，另列共用程式保留的來源訂單及批次配貨分支，不能把分支當成每次都要走的步驟。

| 情境 | 適用規則 |
| --- | --- |
| 獨立倉管單 | 自行輸入唯一單號，不要求營運系統先有同號訂單；加入件數受可用實體庫存限制，沒有外部訂單數量上限 |
| 已關聯來源訂單的單據 | 來源須有效且版本一致；主副單合計不得超過來源需求 |
| 同號建單 | 程式可能開啟既有主單；來源衝突或多個來源同號時阻擋，不自動改關聯 |
| 批次配貨／揀貨／扣庫待寄 | 共用服務保留的操作與歷史狀態，與日常掃碼主流程分開說明 |

倉管與營運系統各自獨立；本篇不包含跨系統訂單同步。

## 3. 使用者操作流程

**前置條件：** 商品及條碼已建立；實體件完成入庫，位於啟用、允許出貨且符合品質／包裝的櫃位；不在退貨待放行或他單占用中。

| 步驟 | 使用者操作 | 系統回應與核對重點 |
| --- | --- | --- |
| 1. 建單 | 在出貨管理按「建立訂單」，輸入單號，可填通路與備註 | 建立空出貨單並開啟詳情；畫面屬準備中，尚未占用庫存 |
| 2. 加入商品 | 掃描或手動輸入商品條碼，每次一件 | 依 FIFO 取得一件合格實體件並占用，商品表增加一件；不需再按一次配貨 |
| 3. 核對 | 對照實物、商品明細與件數；必要時取消單件 | 取消仍在倉內的本單占用件後釋放占用，更新本輪明細 |
| 4. 完成 | 確認本輪商品後按「完成」 | 再次檢查全部占用件資格，成功後扣除倉內件數並記錄完成；空單不能完成 |
| 5. 查結果 | 查看單據狀態、時間、逐件歷史及出貨總覽 | 狀態為完成，依有效完成事件日計入出貨數 |

**錯誤處理：** 未知條碼、無合格庫存或來源需求已滿時，顯示失敗原因，本次不加入商品；之前已成功掃入的商品保留。操作結果不明時先重新讀取原單，不能直接認定未保存。

**盒損分流：** 掃碼以一般條碼選一般包裝件，以 `#` 前綴條碼選盒損件；兩者仍需符合櫃位出貨資格。批次自動配貨選一般包裝件，不等同盒損掃碼。

## 4. 狀態與庫存變化

畫面的「準備中」包含草稿、已占用、已揀貨及扣庫待寄；不能只看這個標籤判斷是否已扣庫。下表的在庫指帳面 `warehouse` 件數；可用指其中符合出貨條件且未占用的件數。

假設本次操作 N 件，且件況與櫃位資格未變：

| 操作 | 內部狀態變化 | 倉內件數 | 占用與可用變化 |
| --- | --- | --- | --- |
| 建立空單 | → draft | 不變 | 不占用 |
| 成功掃碼一件／配貨 N 件 | draft → allocated，後續掃碼維持 allocated | 不變 | 本單占用增加，可用減少同數 |
| 揀貨（服務分支） | allocated → picked | 不變 | 保留占用 |
| 直接完成 | allocated／picked → shipped | 減 N | 清除本單占用；可用不再扣一次 |
| 扣庫待寄（服務分支） | draft／allocated／picked → staged | 減 N | 商品移到待寄，保留占用；draft 會先自動配貨 |
| 待寄完成 | staged → shipped | 不再減少 | 清除待寄占用，不二次扣庫 |
| 取消未出貨單 | draft／allocated／picked → cancelled | 不變 | 釋放占用；仍合格的件重新可用 |
| 取消待寄單 | staged → cancelled | 加 N | 須走待寄撤銷與歸回確認，釋放占用 |
| 完成回準備中 | shipped → allocated | 加 N | 原件回帳面倉內且由原單占用，可用不增加 |
| 取消單重開 | cancelled → draft | 不變 | 本輪明細為空，不取回歷史件 |

**重要邊界：** 完成單不能直接取消，須先回準備中。現行程式會將原件的帳面位置由客戶端改回倉內，並撤銷原完成事件的統計效力；這不是實際退貨，退貨量不增加。程式不會自行確認商品是否真的已回倉，實物核對與可操作條件仍列為待確認，不能把帳面回復當成實物回復證據。

## 5. 需求與驗收條件

以下五項皆為核心需求（Must）。驗收條件定義預期結果，執行結果需另行記錄。

### SP-11-R01｜配貨資格與 FIFO

- **價值：** 避免超配與跨單搶用同一實體件。
- **規則：** 在符合商品、品質、包裝、櫃位、退貨放行及未占用條件的件中，依 `fifo_at`、實體件 ID 排序取得，不由操作者挑成本。
- **成功範圍：** 掃碼一次是一件；批次配貨一次涵蓋該單本次明細，任一商品不足時整次批次配貨不生效。兩者不可混為「整張單所有歷史操作回滾」。
- **驗收：** 只有一件可用時，兩張單競爭最多一張取得；批次要求 A 兩件、B 兩件但 B 只有一件時，A、B 均不新增占用，原明細保留。
- **前置條件：** 商品已入庫，且符合櫃位出貨資格。

### SP-11-R02｜扣庫時點與操作重送

- **價值：** 出貨與庫存數量一致，避免同一操作重複扣庫。
- **規則：** 空草稿不占用；掃碼成功即占用；日常直接完成才移出倉內。另有扣庫待寄分支，已扣庫待寄的件完成時不得再扣。
- **驗收：** 初始在庫 10、占用 0、可用 10；掃入三件後為 10／3／7；直接完成後為 7／0／7。重送同一完成操作，數字維持不變。
- **補充：** 重送同一掃碼操作識別碼應返回同一結果；再次以新操作掃同條碼屬新增一件，不應誤判為重送。
- **前置條件：** 通過配貨資格與 FIFO 檢查。

### SP-11-R03｜主副單與需求上限

- **價值：** 支援分批處理，保留各單獨立狀態。
- **規則：** 從主單建立唯一編號副單，不從副單再建副單；建立空副單與加入商品分開判斷。主單取消不自動取消已完成副單。
- **來源訂單驗收：** 需求 A 共 10 件，主單已完成六件，副單可再加入四件，第五件被阻擋。主單完成回準備中仍占六件，上限不釋放；再取消才釋放該六件需求。已完成副單保持四件。
- **獨立倉管驗收：** 無外部需求上限，主副單各自加入可用件；仍不得共用同一實體件。
- **適用邊界：** 來源訂單檢查僅適用關聯訂單的單據，獨立倉管單可自行建立。

### SP-11-R04｜完成撤銷與重開

- **價值：** 更正操作時保留原件追溯，避免釋放後又搶回他單商品。
- **規則：** 完成回準備中保留原件、成本及 FIFO，撤銷原有效完成事件並增加重開輪次；取消才釋放。取消重開只開空單，歷史仍保留。
- **阻擋條件：** 任一原件已實退、轉單、被占用、位置改變，或有效出貨件數不完整，整單不得回準備中。舊輪次操作不得修改新輪次。
- **驗收：** 完成三件後回準備中，帳面在庫回增三件且占用三件，可用不增加；取消後另一單取得原件，再重開舊單時明細為空，另一單占用不變。
- **待確認：** 撤銷完成時的實物核對政策；已發生實際退貨時應依退貨流程處理。

### SP-11-R05｜時間、歷史與報表

- **價值：** 可查原始操作，又不重複計入已撤銷的出貨。
- **規則：** 分別顯示建立、首次完成、最近取消時間；首次完成不因再完成覆寫，重送取消不刷新時間。逐件保留來源入庫、成本、占用、出貨、釋放及重開歷史。
- **統計口徑：** 出貨總覽依有效出貨／實退事件日；撤銷完成不增加退貨件數。再完成以新事件日計數；同履約群組可有多張單，訂單數與出貨單數分開。
- **驗收：** 1 月 2 日完成兩件，2 月 1 日回準備中，2 月 2 日再完成。以 3 月 1 日為查詢時點，1 月出貨零件、2 月兩件、退貨零件；首次完成仍為 1 月 2 日。以 1 月 31 日為歷史查詢時點，仍能看到當時已完成的兩件。
- **相關規則：** 成本依入庫與成本修訂紀錄計算，實際退貨依退貨事件計數。

## 6. 共同驗收方式

所有案例均使用隔離測試資料，不讀取或重建工作庫。先核對服務與資料結果，再由真實瀏覽器重現主要流程；兩種結果分開記錄。

| 案例 | 前提與操作 | 預期結果 |
| --- | --- | --- |
| A：缺貨掃碼 | 只有兩件合格品，連續掃三次 | 前兩件成功占用，第三次失敗；本單仍有兩件 |
| B：資格不符 | 商品在停用櫃、不可出貨櫃或退貨待放行 | 不加入；顯示失敗原因，既有占用不變 |
| C：空單完成 | 新建空單 | 介面不提供完成；服務也不得完成或產生扣庫事件 |
| D：占用後條件變更 | 掃入後停用所在櫃，再按完成 | 完成被阻擋，不產生部分出貨；重新核對資格 |
| E：部分實退 | 完成兩件，其中一件完成實際退貨登記，再整單重開 | 阻擋整單重開，不改另一件及退貨紀錄 |
| F：舊畫面重送 | 單據已重開，舊畫面提交舊輪次完成或取消 | 衝突提示，重新讀取單據；新輪次不被修改 |
| G：回應遺失 | 同一操作已成功但回應遺失，以同操作識別碼重試 | 不重複占用、扣庫或新增完成事件 |

每次保留：前後單據狀態、實體件 ID、倉內／占用／可用件數、有效事件及錯誤訊息。未知值、查詢失敗與零件須區分。

## 7. 成效衡量

以下是後續觀測定義，不是已取得的成果或承諾值。

| 指標 | 定義與取得方式 |
| --- | --- |
| 出貨任務完成率 | 指定情境中正確完成且庫存一致的任務數／有效受測任務數，由驗收紀錄計算 |
| 操作時間 | 從開啟建單到完成的實際操作時間，按件數與情境分組，另記錄等待／中斷 |
| 人工補救比例 | 需人工釐清或更正才能完成的任務數／有效受測任務數，記錄原因 |
| 庫存一致性 | 驗收後逐件位置、占用、單據及報表核對是否一致；異常不得以速度改善抵銷 |

基準、目標值、觀測期間及負責人待確認；現有事件未必能獨立還原操作時間，需搭配測試記錄。

## 8. 待確認與範圍外

1. **完成重開的實物核對：** 哪些誤操作可撤銷完成？實際已寄出時由誰確認？是否需填理由？目前有帳面回復機制，實物回倉確認方式仍待定義。
2. **待寄取消：** 現有畫面送出歸回確認與固定原因；是否需增加操作者明確核對實物的步驟，列為提案。
3. **掃碼設備與分工：** 目前可掃碼或手動輸入；指定設備相容性、多人揀貨分工及角色授權需另訂範圍與驗收條件。
4. **來源訂單模式：** 倉管日常採獨立建單；保留的來源訂單分支僅記錄相容行為，未新增跨系統交換。
