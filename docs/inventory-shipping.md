# 庫存與出貨指南

[回到專案首頁](../README.md) · [商品採購指南](goods-purchases.md) · [工廠生產指南](production-workflow.md)

## 使用目標

這份指南帶倉管人員從建立商品、入庫及配櫃，走到自行建立出貨單與核對出貨總覽。本系統不接收營運系統的訂單；出貨單號由倉管端自行決定。

## 前置條件

- 商品庫已有啟用中的單品 SKU；若要出貨套組，需先核對組成單品。
- 需要實際扣庫存時，先在「櫃位管理」建立並啟用符合商品條件、允許出貨的櫃位。
- 準備真實收貨與出貨依據。未知的費用留白，不以 `0` 代替。

## 操作流程

```text
建立商品 → 入庫確認 → 配櫃 → 建立出貨單 → 加入商品與配貨 → 完成出貨 → 核對總覽
```

### 1. 建立商品並入庫（Step 1）

在「商品與庫存 → SKU 商品庫」建立商品名稱、SKU 和需要使用的條碼。從「入庫管理」建立入庫單，填寫商品與本次實收數量；核對後確認入庫。商品採購或工廠生產也能產生關聯入庫單，詳細步驟見各自指南。

確認入庫後，到庫存總覽核對實體件數與入庫單。此時商品可能仍是未配櫃，不代表可以直接出貨。

### 2. 配置可出貨櫃位

在「櫃位管理」設定櫃位與啟用狀態，再從入庫單的配櫃入口，或從「配櫃」工作區安排商品位置。完成後核對商品、數量與櫃位。品質、包裝、櫃位狀態或既有占用不符時，畫面的可出貨數量可能低於實體在庫。

需要移動庫存時使用「調撥管理」，保留原櫃與目的櫃的紀錄。不要以重新入庫代替調撥。

### 3. 自行建立出貨單

進入「出貨作業 → 出貨管理」，按畫面的「建立訂單」，輸入倉管端使用的唯一編號，可填出貨通路與備註後保存。這個入口建立的是本系統的出貨單，不要求營運系統先有同號訂單。

在出貨單詳情加入本次要出的商品與數量，核對可用庫存後依畫面完成配貨、揀貨與出貨。沒有商品明細的空出貨單不能完成出貨；庫存不足或所在櫃位不具出貨資格時，也不能強行扣庫存。

若同一筆作業需分批處理，可從主單建立副單，各單狀態獨立。出貨前如需取消，先確認已占用商品的釋放狀態；已完成出貨的商品應依實際退回事件處理，不以刪除出貨單抵銷。

### 4. 核對出貨總覽

到「報表與分析 → 出貨總覽」選擇日期、通路或商品 SKU。這裡依**實際完成出貨與退貨的日期**統計，不代表營運系統的下單日銷售數字。核對出貨單數、出貨件數與退回件數，必要時回到原出貨單查看逐件歷史。

## 完成後驗證

- 商品庫、入庫單和庫存總覽的 SKU 與實體件數一致。
- 櫃位啟用且符合品質、包裝和出貨設定；可出貨件數不超過實體在庫。
- 每張出貨單有唯一編號，商品明細、配貨狀態及實際完成時間可追查。
- 出貨總覽的期間與單據狀態符合本次查詢，不把待出貨當作已出貨。

## 常見問題與排錯（Troubleshooting）

| 狀況 | 先核對 |
| --- | --- |
| 已入庫卻無法配貨 | 是否完成配櫃；櫃位是否啟用且允許出貨；品質、包裝或占用是否限制這些商品 |
| 出貨單編號已存在 | 先搜尋原單，確認是否已保存，避免換編號重建同一筆作業 |
| 完成後需要退貨 | 先核對實物是否回到倉庫，再依退貨流程記錄，不直接增加一般品可用量 |
| 出貨總覽與銷售數字不同 | 兩套系統資料不交換；出貨總覽依實際出退貨日，營運銷售依下單日 |

本指南依 2026-11-04 的倉管介面與程式碼整理。新拆出的倉管包尚未完成真實瀏覽器全流程驗收；按鈕或出貨規則變更時應同步更新本頁。
